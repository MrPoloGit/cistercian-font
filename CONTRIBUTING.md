# Contributing

## Setup

```
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pre-commit install
```

Requires Python 3.10+.

## Running checks locally

```
ruff format src tests
ruff check src tests
mypy src
pytest --cov --cov-report=term-missing
```

All four run in CI (`.github/workflows/ci.yml`) on Python 3.10, 3.11 and 3.12.
`pytest` fails the build below 90% coverage of `src/cistercian`.

## Building the font

```
cistercian build --out dist
```

`--numbers 100` builds a small subset (fast, for local iteration); omit it, or
pass `--numbers all`, for the full 0-9999 range. See `cistercian build --help`
and `cistercian merge --help`.

## Style

### Python

- **Version:** Python 3.10 or newer, declared in `pyproject.toml`.
- **Formatter and linter:** `ruff` for both (`ruff format` and `ruff check`). No separate black or isort.
  - Line length 88.
  - Double quotes for strings.
  - Enabled rule sets: `E`, `F`, `W`, `I` (import order), `N` (naming), `UP` (modern syntax), `B` (bugbear), `SIM`, `RUF`.
- **Type hints:** all public functions are fully annotated. `mypy --strict` runs on `src/`. Tests may be looser.
- **Naming:**
  - Modules, functions and variables use `snake_case`.
  - Classes use `PascalCase`.
  - Constants use `UPPER_SNAKE_CASE`.
  - Glyph names follow one scheme and are generated by a single helper, never typed by hand: `cistercian.units.N`, `cistercian.tens.N`, `cistercian.hundreds.N`, `cistercian.thousands.N`, `cistercian.num.NNNN` (zero-padded).
- **Code points:** written as hex constants with names (`UNITS_BASE = 0xEBA0`), never as bare numbers in logic.
- **Structure:**
  - Geometry, glyph building, features and font assembly stay in separate modules. Geometry has no fontTools imports so it can be tested alone.
  - Functions are pure where possible, taking the spec and returning outlines.
  - No global state. The spec is loaded once and passed in.
- **Docstrings:** Google style on every public function and class. Say what coordinates and units mean (font units, y-up).
- **Comments:** explain why, not what. Document the reason for any choice that follows the proposal or a font-format quirk.
- **Errors:** raise specific exceptions (`SpecError`, `MergeError`) with messages that name the offending glyph or file. No bare `except`.
- **Determinism:** builds are reproducible. Sort everything that is written to the font, and set the font's timestamps from `SOURCE_DATE_EPOCH` when it is set.

### Spec files (JSON)

- 2-space indent, UTF-8, trailing newline, keys in a fixed order.
- Coordinates are integers in font units, on a documented grid (for example 1000 units per em).
- A JSON Schema file validates `digits.json` and `letters.json`, and the build fails on invalid input.

### Tests

- `pytest`, with one test file per module. Test names read as sentences (`test_zero_is_bare_stave`).
- Property-style checks over the whole 0–9999 range instead of hand-picked cases where possible.
- Coverage target of 90% for `src/`, checked in CI.
- Shaping tests use HarfBuzz and compare glyph names.

### Other files

- **Markdown:** wrapped at about 100 characters, one sentence per line where it helps diffs, fenced code blocks with a language.
- **YAML (workflows):** 2-space indent, pinned action versions.
- **JS/HTML (demo):** 2-space indent, `prettier` defaults, no build step, no dependencies.
- **`.editorconfig`:** UTF-8, LF line endings, final newline, trim trailing whitespace, 4 spaces for Python and 2 for everything else.

### Tooling and workflow

- **Pre-commit hooks:** `ruff format`, `ruff check`, `mypy`, a JSON-schema check of `spec/`, and trailing-whitespace and end-of-file fixers.
- **CI (`ci.yml`):** the same checks plus `pytest` on Python 3.10, 3.11 and 3.12 for every push and pull request.
- **Commits:** Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `build:`, `chore:`), subject line under 72 characters, imperative mood.
- **Branches and pull requests:** short-lived branches off `main`, one logical change per pull request, tests required for new behavior, and CI must pass before merge.
- **Versioning:** semantic versioning. Font releases are tagged `vX.Y.Z`, and the version is written into the font's name table from one place.
- **Changelog:** `CHANGELOG.md` in Keep a Changelog format, updated with each release.

## Commits and pull requests

- [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`,
  `fix:`, `docs:`, `test:`, `build:`, `chore:`), imperative mood, subject
  line under 72 characters.
- Short-lived branches off `main`; one logical change per pull request.
- Add tests for new behavior; CI must pass before merge.

## Spec files

`spec/digits.json` and `spec/letters.json` are validated against the JSON
Schema files in `spec/schema/` on load (and in CI). If you change a spec's
shape, update its schema in the same commit.
